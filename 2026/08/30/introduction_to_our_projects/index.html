Introduction§

The following post will be the introduction to our (Dominik Gęgotek and Agnieszka Gęgotek) current projects. In it we will describe the objectives, intermediate goals and some of the steps that we wish to take in order to achieve our plans. But let’s start from the beginning.

Main goal

Our main goal is to study the communication process on GitHub to establish how project coordinators can improve their communication skills in order to attract more volunteers to contribute and retain the cooperation with them for a long time.

Why did we actually come up with this project?§

Since we both had some experience in software development on GitHub, we quickly came to a conclusion that the communication there varies from coordinator to coordinator and project to project and since we are free and open source software enthusiasts, we wanted to do something that can possibly benefit the community. Thus, we started analysing the communication in open source projects. Our main areas of interests are sentiment analysis, values and hedge phrases. And the main research questions that we wish to answer in our projects are:

  • What language strategies are effective in encouraging volunteers to cooperate?
  • What are volunteers’ beliefs about the directness of code feedback?
  • What are the beliefs of project managers regarding effective communication with contributors?
  • How is the balance between politeness and transparency achieved in code reviews?
  • How are community values ​​reflected in the communication process between project managers and volunteers?
  • How is code evaluation communicated? How is it perceived by volunteers, depending on the sentiment of the statement?
  • How do volunteers perceive their role in developing free software projects in the context of the values ​​these projects refer to in their public profiles and ethical codes?
  • What role do positive and negative sentiment play in communication with volunteers?

Gathering data§

To answer them, we obviously needed some data and having previous experience with corpus analysis, we decided that we will create a corpus of open source communication using GitHub API. This is because we did not find any existing corpus that would suit our needs. For now, the corpus has about 5 billion words (but we will describe it in more detail in a different post). However, there was one problem with the corpus - none of the existing corpus tools that we tested, were a good fit for the analysis we have planned. Therefore, we decided to create our own tool.

Corpus tool§

Through our previous works we established that corpus linguistic tools lack a feature that is rather important for communication in open source projects or in general - that is tracking and querying the context. Of course, having common corpus data such as word frequency or collocations is important, but in many cases the full context is also crucial. The meaning of some sentences may change depending on who wrote them - coordinator, a long-time contributor or a person new to a community. The topic of each pull request and issue, date of posting the comment, reactions and responses it received are also important. Therefore, the corpus we are creating will be compiled in a form of a database, where each piece of information will have its designated place and can be retrieved if needed. Moreover, the database will be created using DuckDB - an open source Relational Database Management System (you can read more about it here or in future posts).

The program we aim to create will be based on database queries that are well-known in other areas of science and look like this:

1

SELECT "comments".body, "comments".frown_number FROM "comments" ORDER BY frown_number DESC;

This query will find all of the comments with the most 🙁 reactions and display them in a descending order.

Future development§

In the future, we wish to share the database together with the tool through a website for other researchers to use as well. Each user will be able to create their own queries to look for specific words, comments from a given project, etc. At first, the corpus will use only those queries, but in the future we also want to implement a graphical interface that will allow users who are not comfortable with the query language to be able to conduct their own studies without the need of learning the SQL language.

That is the main idea behind our project. In the following posts, we will describe updates concerning the development of the corpus, tool and methodologies used for our research.
