An interview with Richard Stallman

Table of Contents
  1. Introduction
  2. The interview

Introduction§

This is an interview with Free Software Movement initiator - Richard Stallman. The interview focuses on communication during free software development and the possible similarities with citizen science initiatives. The interview was conducted from 13 April 2025 to 24 September 2025 through email correspondence. The questions are shared under CC-BY © Agnieszka Gęgotek and Dominik Gęgotekwhile the responses are under CC-BY © Richard Stallman.

The interview§

Below is the text of the interview. The questions are preceeded by “Q:” and marked in bold and Richard Stallman’s answers are preceeded with “A:”.

Q: 1. How would you define free software?

A: Free software means software that respects the users’ freedom. A crucial consequence of this is that the users control the software.

There are four essential freedoms that every user of software is entitled to:

Freedom 0: the freedom to run the program as you wish.

Freedom 1: the freedom to change the program so that it runs the way you wish. For users to exercise this freedom, they need access to the program’s source code, and a way to rebuild it from modified source code and run that build.

Freedom 2: the freedom to make exact copies and to give or sell them to others when they wish. This includes the source form of the program, and any compiled forms the users may make.

Freedom 3: the freedom to make copies of their modified versions, and give or sell them to others when they wish. Users doing so must be permitted to distribute modified versions as free software. (Some free licenses require that all modified versions distributed be free.)

If a program gives the users these freedoms, the program is free software for them. As a consequence, the users control the computing they do with it.

When users use a nonfree program, they don’t control it. Rather, its developer controls the program, and the program controls the users. Thus, that program gives the developer power over the users.

That power is what makes any nonfree program an injustice.

Q: 2. What values does free software movement represent in your eyes?

A: The values of the free software movement start with liberty, equality and fraternity, the Rights of Humanity affirmed by the French revolution. To uphold these rights in the software field calls for insisting that software be free.

Our values continue with the values of what is good: truth, justice and beauty. Nonfree software usually hides the truth and leads to injustice.

Q: 3. Is free software important for academia? If yes, how?

A: Freedom is vital for all users – using a nonfree program implies being subjugated by someone or other. This is true always and everywhere, inside academia and outside.

However, free software has a special importance in academia, and in schools of any kind and level. A school must uphold education and the sharing of knowledge. So it must not ask a student to use a program that denies students the knowledge that its source code embodies. A school must encourage people to make use of their knowledge by changing, improving and adapting the program’s code.

Only free software does that.

Q: 4. Citizen Science could be defined as a movement that is focused on allowing non-scientists and laymen to collaborate with specialists, contribute to the development of scientific research, discuss the findings and share ideas. Do you think that free software projects are similar? If yes, in what way?

A: There is an obvious similarity in spirit, but there is also a difference, because a free program is typically meant for practical use of some kind. When a group of users improve it, often their changes are meant specifically to make the program more convenient or more effective in practice, for their use. Most research projects are not directly practically useful in that way, and don’t need to be, since they contribute to scientific knowledge rather than directly to use.

Q: 5. Can free software contributors develop new skills while contributing and discussing code? Does the development of free software have an educational value? If yes, in what way?

A: Contributors can learn mastery of programming by writing software that is useful. However, in order for this to make real contributions to the community’s software, those contributors must be quite capable already. Beginners trying to help are likely to use up more of the developers’ time than their contributions are worth.

Q: 6. Why is development of free software important?

A: Maybe I misunderstand the question, because it seems obvious to me. To do computing without bowing to some software owner as overlord, we need need free software to do it with. To have free programs to do all the computing tasks, we need people to write them.

If the question has some other meaning, please tell me.

Q: 7. How important is cooperation for free software projects?

A: A free software project does not inherently require many cooperating developers. If you succeed by yourself in developing the program you want, and release it, there is nothing wrong with doing it that way.

However, a group of capable people working together and cooperating can achieve much more than a single capable individual. The cooperation in our community is what enabled us to develop a complete free operating system such as GNU/Linux.

Q: 8. Is encouraging and keeping contributors engaged in the project difficult? Would it be beneficial to sustain their involvement in the project for longer?

A: There is no general answer to questions like that. When a specific set of people are trying to work together as a group, you’re in the domain of human relationships. Each group is made up of various people. Some groups keep working together for decades, while others split up. That is life.

I think that encouraging kindness in communication helps groups work together with less friction. So I wrote some suggestions: https://gnu.org/philosophy/kind-communication.html

Q: 9. Do you agree that the study of issue/pull request communication in free software would be beneficial? If yes, in what way?

A: I am not sure what “the study of issue/pull request communication” means. Could you say it more concretely?

Q: 10. Do you agree that the study of issue/pull request communication in free software would be beneficial? We mean here for instance:

  • how the contributors prefer to be addressed?

  • does the directness of response have an influence on further cooperation?

  • is the feedback understandable and applied in the revisions of the pull request?

  • how the sentiment/tone of the code reviews influences further cooperation with the contributor?

  • how to achieve balance between directness and politeness?

A: These seem to suggest projects to quantify details of human relationships. I don’t know how that can be done – for me, in human relationships, all I can do is wing it. I won’t say such quantitative study is useless, I just don’t know.

I don’t use the term “pull request”, because that term is used mainly in connection with GitHub – a site that has used its influence in many ways that undermine the free software movement. Even to make an account on GitHub requires running nonfree JavaScript code, so I do not have an account there.

We urge developers not to host their software on GitHub. See https://www.gnu.org/software/repo-criteria-evaluation.html for more details.
